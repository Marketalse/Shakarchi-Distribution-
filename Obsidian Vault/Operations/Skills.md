# Contributor and agent skills
| Playbook | When to apply | Deliverable |
|---|---|---|
| Requirements mapping | A request changes the visit or a business rule | Source, requirement, acceptance example and open decision |
| Postgres and access review | A schema or report changes | FK/constraint review, synthetic cases and owner/rep access matrix |
| Offline field UX | A form, sync rule or permission changes | Figma or annotated sketch if approved; no-signal/retry/permission scenarios |
| Finance reconciliation | A money workflow changes | Synthetic invoice, partial payment, return, credit and reversal examples |
| Field QA | Before pilot or rollout | Device/network matrix, timing and anonymized evidence |
| Reporting and advisor | A metric or weekly insight is proposed | Formula, grain, date range, source count and sample brief |
| Delivery management | Work enters, moves or closes | GitHub issue with owner role, dependency, milestone and evidence |

Use a deeper reasoning model for architecture and policy review, a general coding model for implementation later, and a lightweight model for structured drafts. Evaluate alternatives on the same synthetic cases; retain a human review gate and document vendor/model choices before connecting services. Where an agent follows these playbooks, [AGENTS.md](../../AGENTS.md) defines the repository boundaries.
