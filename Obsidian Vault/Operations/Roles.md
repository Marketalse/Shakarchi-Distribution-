# Roles and responsibilities
| Role | Owns | Approval / boundaries |
|---|---|---|
| Sponsor / product owner (Hesham) | Scope, inputs, budget, go/no-go, pilot | Accepts blueprint and stage exits |
| Delivery lead | Triage, roadmap, dependencies, release checklist | Maintains GitHub tracker; captures decisions |
| Builder / maintainer | Schema, app and integration designs; reviewable PRs | Proposes work; keeps app changes outside setup |
| Finance reviewer | Terms, returns, collections, invoices, account reconciliation | Accepts money semantics and sample reconciliations |
| Field pilot operator | Outlet data quality, timing, poor-signal scenarios | Reports evidence with anonymized examples |
| Independent reviewer | Access controls, sync integrity, recovery | Reviews boundary cases before rollout |
| Analytics owner | KPI definitions, BI access, advisor evaluation | Approves formulas, data minimization and recipients |

One person may hold several project roles. Unassigned roles remain responsibilities to cover, with no implied GitHub invitations. App access is currently owner/rep; proposed Finance, Supervisor and other V2 roles are separate design work.
