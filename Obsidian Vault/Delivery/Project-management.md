# Project management
GitHub Issues owns task state; milestones group phase gates. The vault owns durable requirements, decisions and design. Notion is a source reference. Record status, next action, owner and dependency on the issue, with links to reviewable evidence.

- Intake: use a repository template; identify phase, priority, blocker, acceptance evidence and responsible role. Check for duplicate work.
- Status: Backlog → Ready → In progress → Review → Done; Blocked records the decision or prerequisite and who can resolve it.
- Ready: approved scope, one owner, explicit dependencies and verifiable acceptance. Done: evidence and review linked, documentation reconciled and owner accepts applicable gate.
- Weekly: verify current phase, list blockers, log decisions, reforecast dates and review risky scope. Update GitHub rather than maintaining a parallel board.
- Prefer small focused branches, a PR linked to its issue, and independent review for data/access changes. Use synthetic examples on public GitHub.
